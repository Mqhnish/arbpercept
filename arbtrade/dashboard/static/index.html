How a gap becomes a trade

Each gap is scored at the latency it will face before the orders arrive:

S(τ) = q(τ)·(ê − c) + (1 − q(τ))·ℓ̄(τ)

q is the probability that both immediate-or-cancel legs fill at the prices we saw, after latency τ. ê is the gap measured against the venues' usual offset, c is both legs' fees, and ℓ̄ is the average outcome when a trade does not fully fill.

How to read it. Left to right. The fast path measures the gap against the usual offset (1.8 µs). The decay prior estimates q (1.5 µs). A confident score acts or skips at once; an unsure one waits for the slow model (23 features, 15 µs). Orders then take 50 ms to Binance and 8 ms to Bybit.

Trading every gap loses money

The naive policy trades every gap the fast path flags. It loses $94 to $925 a day on every coin, on the same replays, fees and latency.

How to read it. Bars are the mean realised loss per validation day. This is the cost of ignoring decay: most gaps are gone, or too small, by the time the orders land.

Will the gap last?

Walk-forward AUC for predicting that a gap above 1 bps is still open 500 ms later. The decay model reaches 0.78 to 0.84 on the cross-venue and basis pairs; gap size alone gets 0.49 to 0.58.

How to read it. 0.5 is no skill. Dots are the boosted model, circles gap size alone. On our own 10 ms recordings the model scores 0.64 to 0.74 at 50 to 500 ms, so these archive figures are an upper bound.

Terms used across the site

Naive
trades every gap the fast path flags
Gap size only
the same expected-value rule, with q estimated from the gap's size alone: the obvious baseline
Prior only
uses only the cheap logistic model of q
Slow always
waits for the gradient-boosted model on every gap
Cascade
the prior first, the slow model only when the prior is unsure
Optimistic fills
the last 100 ms Bybit snapshot before an order arrives is taken as still valid when it lands
Conservative fills
a leg fills only if the snapshots on both sides of its arrival allow it, at the worse price and the smaller size
$50k cap
a trade that would push the net position past $50k is skipped
Setups v3 to v9
successive versions of the replay; v9 has every fix and is the one to read

Paper trader

runs on a local checkout

The paper trader connects to Binance and Bybit's live order books, watches the gap against their usual offset, and simulates both legs of every trade it would take. No orders are sent. It needs a live connection to the exchanges, so this static copy cannot run it. To try it, start the dashboard locally (python -m arbtrade.dashboard --open, see Overview) and open this tab.
